# 便利贴墙项目需求

在线体验：[日光留言墙](https://stickywall.parva.cool/)，由 Parva 部署，可直接查看项目效果。

## 一、项目概述

一个 Web 端公共便利贴墙，任何人都可以在墙上贴一张便利贴，写下自己想说的话。

整体风格温暖、自然、惬意、简洁，像一面真实的便利贴墙，而不是传统的论坛或信息流。

## 二、核心功能

### 1. 便利贴发布
- 用户可以发布文字便利贴。
- 发布时选择分类，不同分类对应不同颜色。
- 发布器与真实纸笺对应：顶部小标签选择分类，中间写正文，左下署名，右下贴上墙；保留字数和错误反馈。
- 纸外可选短笺 6 行、方笺 9 行、长笺 12 行，默认方笺。写满后拒绝继续新增或整段超量粘贴，保留已有稿；输入法组字结束后才校验，缩小装不下时保留原尺寸。总上限为 500 个 Unicode 字符。
- 发布时保存所选纸型；正文在其他设备上可自然增高，不裁字或内部滚动。旧记录沿用 auto 布局。
- 所有便利贴都展示在同一面公共墙上。

### 2. 无限生长的便利贴墙
- **新的便利贴始终出现在最上方，旧的逐渐沉积到下方。**
- 墙体可以不断向上生长，向下滚动可以浏览越来越久远的留言。
- 按发布时间倒序排列，不覆盖、不删除旧便利贴。
- 新留言出现时，不打断正在浏览历史内容的用户。
- 接近已加载内容底部时自动加载更早留言，加载中显示简短状态；失败保留现有内容并提供重试，读到底不添加结束说明。

### 3. 分类与筛选
- 所有分类的便利贴默认混合展示。
- 不同分类使用不同的柔和颜色区分。
- 单选「全部」或其中一个分类，默认展示全部分类。
- 分类菜单在当前位置吸顶，滚动时纸笺从菜单下方经过。
- 菜单容器透明，未选中按钮仅加中性小底，按钮间继续展示下方纸笺；选中项保留对应纸色，并通过深色描边、较重字重和勾号明确状态，全部选项同样明显。
- 筛选后自动重新排列剩余便利贴，不留下空洞。
- 无论如何筛选，始终保持时间倒序。

## 三、界面与视觉设计

- **整体风格：** 温暖、清新、自然、惬意，有生活气息。
- **背景：** 浅米色、暖白色等柔和颜色。
- **便利贴：** 淡黄、淡粉、淡绿、淡蓝等低饱和度颜色，带轻微阴影和随机小角度倾斜。
- **排列方式：** 自然错落、不规则分布，不追求整齐对齐。
- **空间布局：** 保持大量留白，便利贴之间有舒适的间距，避免密集堆叠。
- **装饰：** 可以适当加入少量简笔植物、阳光等元素，但不能过于复杂。
- **交互：** 简单直观，提供发布入口、分类筛选和上下滚动浏览。

## 四、响应式适配

兼容手机、平板、电脑等不同屏幕尺寸。

- **手机：** 以单列为主，便利贴自然向下延伸。
- **平板：** 采用宽松的双列错落布局。
- **电脑：** 采用居中的墙体布局，以两列为主，左右保留充分留白。
- **超宽屏：** 限制墙体最大宽度，不因为屏幕变宽而无限增加列数。

不同设备可以采用不同的排列方式，但展示的是同一批内容，时间顺序保持一致。

便利贴的随机倾斜、错位效果应当稳定，不因每次刷新页面而随意变化。

## 五、技术要求

- Web 应用，支持自行部署。
- 前后端实现保持轻量，避免不必要的复杂架构。
- 历史便利贴采用接近底部自动分页，避免一次加载全部数据；切换分类取消旧分页，追加时去重并保留时间顺序。
- 通过响应式布局实现自然错落的排列，不依赖复杂的画布或 3D 渲染。
- 数据持久化保存，方便长期运行。

## 六、核心设计原则

**这是一面可以不断生长、承载陌生人留言的公共便利贴墙。**

它不追求信息密度，也不强调社交关系，而是让每个人都能随手留下自己的想法，让后来的人在浏览中偶然发现。

新故事不断出现在上方，旧故事静静留在下方。整面墙随着时间不断延伸。

## 七、实现与运行

项目名称：**日光留言墙**。前端采用 React + Vite + TypeScript，后端采用 Go 标准库 HTTP + pgx，数据存储在 PostgreSQL。

已实现匿名发布、可选昵称、四类纸色、单选分类筛选、原位吸顶分类菜单、时间倒序、接近底部自动加载历史、稳定倾斜与错位、手机单列与桌面双列。选中分类通过纸色、描边、字重和勾号明确表达；默认展示全部，发布成功后恢复全部分类。历史末端进入距视口 800px 的预取区时自动加载下一页，失败保留现有内容并显示「重试加载」，没有常规分页按钮。发布器为 280px 宽的真实纸笺布局，纸外选 6/9/12 行纸型，顶部选择分类、正文居中、左下署名、右下贴上墙；以同字体、宽度和 36px 行高的隐藏镜像测量实际容量，计数显示已用行数、总行数和字数。矮屏或键盘出现时由外层对话框滚动整张纸，书写区不内部滚动，根页面保留原生滚动条。每 15 秒检查一次新留言，只显示提示，点击后才更新墙面，阅读历史时不会被推走。发布失败保留草稿，服务端保留 500 字上限、校验所选纸型显式换行并限制发布频率。

### 本地开发（Windows）

```powershell
# 首次准备 Go、PostgreSQL 到项目内被忽略的 .local 目录。
./scripts/setup-local.ps1
./scripts/dev.ps1
```

打开 [本地留言墙](http://127.0.0.1:5173)。当前电脑已完成环境准备。

```powershell
# 停止前后端，保留数据库和留言
./scripts/dev.ps1 -Stop

# 可选：只向空数据库手动导入示例，不随应用自动执行
./scripts/seed-demo.ps1
```

### 自行部署

```powershell
Copy-Item .env.example .env
# 将 .env 里的 POSTGRES_PASSWORD 改为自己的 URL-safe 随机密码
docker compose up -d --build
```

应用默认位于 [本机 8080 端口](http://127.0.0.1:8080)，由 Go 同源提供前端和 API。PostgreSQL 使用持久数据卷。公网部署可在前面配置 HTTPS 反向代理，具体环境变量和操作见 [运行说明](docs/running.md)，接口说明见 [后端文档](server/README.md)。

### 项目结构

```text
web/             React 页面、样式、前端测试
server/          Go API、PostgreSQL 表结构与集成测试
scripts/         本地环境、启停与手动示例导入
compose.yaml     应用与 PostgreSQL 的部署配置
PRODUCT.md       已确认的产品约束
DESIGN.md        完成后的视觉规范
```

本地演示留言均以「示例 · 」署名，正式部署不会自动生成留言。检查命令和数据备份相关注意事项见运行说明。
